# Notebook 模板

## 默认结构：技术教程

### 结论与学习目标

开头直接说明本章主题、学习结果和最重要的判断。读者应在三秒内知道文章是否与自己有关。

```text
学完本章，你需要理解以下内容：

1. ...
2. ...
3. ...
```

### 背景与原因

说明技术为什么出现、原有方法遇到了什么问题、当前技术解决哪一部分。

### 核心概念

解释必要概念。每个术语首次出现时给出统一定义，并说明它在完整流程中的作用。

### 参与者与完整流程

先说明参与者及职责，再用流程图或时序图展示数据流动顺序。读者不看代码也应能复述流程。

### 原理拆解

使用表格、清单、数据结构示意或小例子逐步解释协议和状态变化。

### 渐进代码实验

每个实验按以下顺序组织：

1. 目标
2. 输入
3. 当前步骤在完整流程中的位置
4. 小段核心代码
5. 输出
6. 输出解释
7. 断言验证
8. 当前边界

每个代码单元只观察一个关键步骤。完整封装放在读者理解所有步骤之后。

### 完整实验

组装前面已经解释的步骤，执行完整流程。需要模型 API 时，同时提供默认关闭的离线路径和真实调用记录。

### 工程边界

列出权限、重试、幂等、超时、安全、成本和失败处理等真实问题，不让工程细节打断前面的原理主线。

### 本章小结

用清单总结读者现在应该能够解释的结论。

### 与最终项目的关系

用一小节说明当前技术未来可以怎样用于产研协作助手。不得在本章提前实现完整产品功能。

### 下一步

说明下一章继续解决什么技术问题。

---

## 编号与引用格式

长文使用以下标题格式：

```text
# 文章题目

## 1 结论与学习目标

## 2 背景与原因

### 2.1 ...

### 2.2 ...

## 3 核心概念

## 4 完整流程

## 5 渐进实验

## 6 工程边界

## 7 本章小结

## 参考文献
```

要求：

- 文章标题不添加章节编号。
- 正文标题使用 `1`、`1.1`、`1.1.1` 编号。
- 正文引用使用 `[1]` 顺序编码。
- 参考文献采用 `GB/T 7714—2015` 顺序编码制。
- 官方文档和网页资料写明访问日期。
- 摘要、关键词、研究问题、研究方法和讨论等论文栏目不作为默认要求。
- 标题结构服务于阅读顺序，不套用学术论文语言。
